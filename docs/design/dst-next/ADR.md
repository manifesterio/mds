## 1. Decision

dst becomes an actor runtime with built-in effects. Every product machine is an
`actor.Actor[In, IO]` with one input protocol `In` and one sum of real product IO `IO`.
`Receive(now, msg, outbox)` records effects on an `*actor.Outbox[In, IO]`; the runtime
(`sim.System` in tests, `live.Host` in production) carries them out after `Receive` returns.
Wiring uses typed handles only (`EntityRef`, `ReplyTo`, `ServiceRef`). Sum-type boilerplate is
generated by `dstgen`. The old packages (`machine`, `kernel`, `live` v1) are deleted at the end of
P7 (D13).

### 2.1 Amendments made while building P4

These change Appendix A; the code in `dst/core/actor` and `dst/sim` is the reference.

1. **Sends to a handle are methods.** Go cannot infer `P` in `actor.Tell(o, server,
   putValue{...})`: the ref says `P = serverReq`, the argument says `putValue`, and inference
   fails instead of checking assignability. Every protocol is a sum interface, so every call
   site would need `serverReq(putValue{...})`. Methods check the argument against the
   receiver's type instead:
   - `actor.Tell(o, to, msg)` became `to.Tell(o, msg)`.
   - `actor.TellService(o, svc, req)` became `svc.Tell(o, req)`.
   - `actor.Call(o, svc, req, adapt)` became `actor.Call(o, svc.Request(req), adapt)`.
   - `actor.Watch(o, who, gone)` became `o.Watch(who, gone)` (`who` is any `ReplyTo`, through
     the small interface `actor.Asked`).
   - `o` in the methods is an `actor.Sender`: only `*Outbox` implements it.
   `Ask`, `Reply`, `Perform` and `Sub` stay functions: their messages come from closures or
   types with declared types, so inference works.
2. **Refs carry an owner pointer** (`actor.Owner`, made by `actor.NewOwner()` per System or
   Host) instead of a numeric runtime id, so a handle of another System is caught without
   package-level state. It is never folded.
3. **`sim.SpawnOption` is not generic**: `sim.Workload()`, `sim.Attrition()`, `sim.Cost(c)`
   need no type arguments; `WithExecutor`, `OnPhase` and `AfterReceive` infer theirs from their
   function argument and are checked against the actor's types in `Spawn` (protocol failure on a
   mismatch). The attrition config type is `sim.AttritionPlan`.
4. **`sim.ServiceCtx.RecordFault`** records an injected fault (was `Fault` in the sketch): the
   embedded `actor.Faults` already has `Fault(site, p)`, the buggify coin.
5. **Runtime side of `actor`** (`erase.go`): `Effect`, `EffectKind`, `Binding`, `NewOutbox`,
   `Close`, `NewEntityRef`, `NewReplyTo`, `NewServiceRef`, `As`, `Asker`, `ReplyID`. Product code
   does not use them; they are the seam that `sim` and `live` share, and the only place where
   message types are erased.
6. `sim.Tell(sys, to, d, msg)` and `sim.Ask` keep their function form (host code); a concrete
   message needs a conversion or an explicit type argument there.
7. `trace.StringMap(m)` was added (store state hashes), as change 3 of section 9 said.
8. (P6) `sim.AfterReceive(func(self, msg, effects))` also gets the effects of the Receive, as the
   kernel's AfterStep got the outputs: product simulators check what an actor did (the
   controlplane group host checks late writes and answers after a role loss).
9. (P6) `sim.OnEnd(func(self, how, cause))` runs when an incarnation ends, before the restart
   policy: host code stops what depends on the actor (the replica's group actor).
10. (P6) `sim.Ask`'s `done` runs at once while the Reply is applied (not as a later host task), so
    it sees the replying actor as the Reply left it (controlplane's oracle reads the applied
    prefix of the replying replica).

## 3. Runtime model

These terms are used by the guarantees. Both runtimes implement them; "sim" or "live" marks
the places where they differ.

### 3.1 Actor, incarnation, inbox

- An actor is spawned once and gets a stable `EntityRef`. Each boot is a new incarnation with
  a fresh `ID` (sim: drawn from the run stream; live: random) and a fresh actor from
  `Props.New`.
- An incarnation has two inboxes, Control and Data (`Props.Priority`). `Receive` takes Control
  first, then Data, FIFO inside each. The boot message (`Props.Boot`) is always the first
  `Receive` of an incarnation.
- An incarnation ends by `Stop` (Trip or Exit), by a crash from outside (sim: nemesis,
  attrition, stop deadline), or by a panic in `Receive` (Crash).

### 3.2 What an incarnation owns

Owned by one incarnation, dropped when it ends:

- its inbox contents;
- its timers: keyed (`StartTimer`) and one-shot (`After`, `TellSelf`);
- its pending answers: one entry per `Ask`, `Call` and `Perform` not yet answered;
- its watches: one entry per `Watch` not yet fired or cleared;
- its asks as an asker: every `ReplyTo` it handed out dies with it (G4).

### 3.3 Scopes and forgetting

Every timer and pending answer is recorded with a scope: the actor itself, or a `Sub` name
path (`"session"`, `"session/retry"`). Each scope has a forget epoch. `ForgetPending` on an
outbox bumps the epoch of its scope and of every scope below it. A timer or answer whose
recorded epoch is older than its scope's epoch is dropped when it would be delivered. Keys of
keyed timers are stored as `scope + "/" + key` (the actor scope is empty, so actor keys are
stored as written).

### 3.4 Delivery and order

- Every message is delivered by a queue entry ordered by (time, tie, seq) (sim) or by the
  arrival order in the inbox (live).
- Sim lanes: every effect that delivers to an actor at the same virtual time from the same
  source shares one lane, so it is FIFO. A source is one sender incarnation (for `Tell`,
  `Reply`, `TellSelf`, `After`, `StartTimer`, gone of `Watch`), one service (answers), or host
  code (`sim.Tell`, `sim.Ask`). Different sources at the same time are in seeded order. This is
  per-pair FIFO, as in Akka, and replaces the product-side lanes of today (`toMachineLane`).
- Live: one inbox per actor, filled in arrival order. Effects of one `Receive` are enqueued in
  record order, so per-pair FIFO holds too.

### 3.5 Executors

- `Do(io)` and `Perform(req, adapt)` hand the IO value to the executor of the actor, right after
  the `Receive` that recorded it, in record order, on the actor's own step (sim) or goroutine
  (live). The executor must not block.
- Sim: `Executor[IO]` answers a `Perform` with `sim.Answer(ctx, req, d, rep)` or
  `sim.Forward(ctx, req, service)`. Live: the exec function starts the real IO and calls
  `live.Answer(ctx, req, rep)` from any goroutine.
- Unsolicited results (bytes on a socket) are messages the executor sends with `sim.Tell` or
  `live.Tell` (O5).

### 3.6 Outside askers

`sim.Ask` and `live.Ask` create an asker that is not an actor. Its `ReplyTo` dies when the
answer arrives, when `within` passes (sim), when its context ends (live), or when the Host
stops (live).

### 3.7 Live lifecycle

Live does not restart in process: `Props.Restart` is ignored by `live.Host`. When any actor's
incarnation ends, the Host stops the other actors (StopMsg, then kill after `StopGrace`) and
`Run` returns the first end's error (`ErrTripped` with the cause for Trip, nil for Exit during
shutdown, `ErrKilled` if a stop missed its deadline). The process supervisor restarts the
process. This is today's behaviour of controlplane and broker.

### 3.8 Protocol failures

Using the API the wrong way is a protocol failure: sim fails the seed with `FailProtocol`
(as today); live ends the Host with an error. The list: a zero or foreign handle; an Outbox
or Sub outbox used after its `Receive`; any effect after `Stop`; `Stop` through a `Sub`
outbox; a second `sim.Answer` to one `Perform`; a `Spawn` with no `New`, a duplicate `Name`, or
(sim) a non-NoIO actor with no executor; a `Workload` actor that ends.

## 4. Runtime guarantees

Each has a named test in P4 (sim) and P5 (live).

**G1 Effects applied in order** (`TestEffectsAppliedInOrder`). The effects of one `Receive`
take effect after it returns, in the order recorded. Nothing recorded is visible to anyone
before `Receive` returns.
Edge cases:
- Panic in `Receive`: no recorded effect is applied. The incarnation ends as Crash (sim: a
  `Workload` halts the run; live: the Host ends).
- Effects after `Stop` in the same `Receive`: protocol failure; none of them is applied. Effects
  before `Stop` are applied in order before the incarnation ends, so a `Reply` or `Do` recorded
  before `Stop` still goes out.

**G2 Same-time order is seeded** (`TestSameTimeOrderIsSeeded`). Sim: entries due at the same
virtual time run in (time, tie, seq) order. The tie is drawn from the run stream when the entry
is added; entries on one lane at one time share a tie, so they keep insertion order (section
3.4). The same seed gives the same order.
Edge cases:
- `StartTimer(k, 0, m)`, `After(0, m)` and `TellSelf(m)` are due now, after the current `Receive`,
  on the actor's self lane: FIFO among themselves in record order. A negative duration counts
  as 0.
- Two `Tell`s from one actor to one target in one `Receive` arrive in record order.

**G3 Cancel and restart drop a fired timer** (`TestCancelDropsFiredTimer`). `CancelTimer(k)`
drops timer `k` whether it is still pending, or fired and waiting in the inbox. `StartTimer(k,
...)` does the same to the old timer `k` before arming the new one. So a replaced or cancelled
timer's message is never received. One-shot timers (`After`) cannot be cancelled; `Stop` and
`ForgetPending` drop them.

**G4 A ReplyTo dies with its asker** (`TestReplyToCrashedAskerDropped`). A `Reply` (or a
service answer, or an executor answer) to an asker whose incarnation ended, or whose outside
ask ended, is dropped and counted. If the asker restarted, the new incarnation never sees it.
A second `Reply` to the same `ReplyTo` is dropped (not a failure: answering twice after a retry
is normal product behaviour).

**G5 ForgetPending drops pending work** (`TestForgetPendingDropsAnswers`). After
`ForgetPending` in scope S, every timer (keyed and one-shot, pending or fired and waiting) and
every `Ask`, `Call` and `Perform` answer recorded in S or below it before the call is dropped,
now or when it arrives. Effects recorded after `ForgetPending` in the same `Receive` belong to
the new epoch and are kept. Watches and the inbox's other messages are kept. The incarnation
does not end.
Edge cases:
- `ForgetPending` then `Stop` in one `Receive`: legal; `Stop` drops everything anyway.
- `Stop` then `ForgetPending`: protocol failure (an effect after `Stop`).
- `ForgetPending` does not cancel IO already handed to the executor; it only drops the answer.
  A write on the wire can still land (sim services keep `Later` steps, as today).

**G6 Watch fires once** (`TestWatchFiresOnce`). `Watch(who, gone)` delivers `gone` exactly once
if the asker behind `who` ends before a `Reply` to `who` is applied; never otherwise.
"Ends" means: its incarnation ended (sim, live), its `sim.Ask` deadline passed, its `live.Ask`
context ended, or the Host stopped (live; then nobody receives `gone`, because the watcher is
stopping too).
Edge cases:
- `Watch` on an asker that is already gone: `gone` is delivered at once (after this `Receive`).
- `Reply` applied while the asker is alive: the watch is removed; `gone` is never delivered.
- `Reply` applied after the asker ended: the reply is dropped (G4); `gone` was already queued
  and is still delivered. The product must accept `gone` for a call it already answered.
- Two `Watch` calls on the same `ReplyTo`: both fire. The watch belongs to the watcher's
  incarnation; if the watcher ends first, nothing fires.
- `Watch` is not dropped by `ForgetPending`.

**G7 Stop drops everything** (`TestStopDropsEverything`). `Stop(how, cause)` ends the
incarnation after the effects recorded before it. Its inbox, timers, pending answers and
watches are dropped; its outstanding asks die (G4). Sim: `Props.Restart(how, rand)` decides the
next boot; `Exit` during a graceful stop is a normal end; a `Workload` may not stop. Live:
section 3.7.

**G8 Sub behaves like the parent** (`TestSubWrapsMessages`). An effect recorded on
`Sub(o, name, wrap)` behaves exactly like the same effect on `o`, except: messages to self
(`TellSelf`, `After`, `StartTimer` messages, adapted answers, `gone`) are wrapped with `wrap` when
they are delivered; keyed timers live in the scope `name`; `ForgetPending` acts on the scope
`name` only. `Stop` through a sub outbox is a protocol failure. Subs nest (`Sub(sub, ...)`);
wraps compose from the inside out.

**G9 Everything scheduled is in the trace hash** (`TestTraceFoldsPendingTimers`). Sim folds:
every `Receive` (actor name and message), every applied effect (section 5), every queue entry
when it runs (time, kind, lane, target, incarnation, service, body), and after every step the
state of every actor (up, state hash, inbox lengths, busy-until, and the number of its timers,
pending answers and watches) and of every service. Two runs that differ only in a pending
timer differ in hash.

**G10 A Perform answer is scoped** (`TestPerformAnswerScoped`). An executor answer reaches the
incarnation that recorded the `Perform`, and only if its scope's epoch has not moved since
(G5). It is delivered at most once, wrapped by the subs on the way (G8), and adapted by the
`adapt` function recorded with it. An answer for a dropped `Perform` is counted, not delivered.

## 5. Trace fold format (O3)

Unchanged: the per-step fold of the actor name and the message (`h.String(name)`, then
`msg.Fold(h)`), `foldEntry`, `foldState` (extended below), facts (501), field values
(401..405), kernel bodies (901..903) and the queue entry kinds (0, 1, 2, 3, 5, 7).

New tag ranges. Product tags today use 1..399 and 1001..1199, so dst takes 2001..2199:

| Tag | What | Fields folded after the tag, in order |
|---|---|---|
| 2001 | TellSelf | msg |
| 2002 | After | Int64(d), msg |
| 2003 | StartTimer | String(stored key), Int64(d), msg |
| 2004 | CancelTimer | String(stored key) |
| 2005 | Do | io |
| 2006 | Stop | Uint64(how), String(cause) |
| 2007 | Fact | fact (tag 501 ...) |
| 2008 | ForgetPending | String(scope), Uint64(new epoch) |
| 2009 | Tell | target EntityRef, msg |
| 2010 | TellService | target ServiceRef, req |
| 2011 | Ask | target EntityRef, the new ReplyTo, the request made by makeReq |
| 2012 | Call | target ServiceRef, Uint64(pending number), req |
| 2013 | Reply | ReplyTo, answer |
| 2014 | Perform | Uint64(pending number), io |
| 2015 | Watch | ReplyTo, gone |
| 2016 | Sub prefix | String(name), then the wrapped effect's own tag and fields |
| 2017 | Executor answer scheduled (sim.Answer, Forward) | Uint64(pending number), Int64(d), answer |
| 2018 | Dropped delivery (stale timer, forgotten answer, dead ReplyTo) | Uint64(reason), target name |
| 2101 | EntityRef | String(name) |
| 2102 | ReplyTo | Uint64(asker kind: 0 zero, 1 actor, 2 sim outside, 3 live outside), String(asker name), Bytes(boot), Uint64(ask number) |
| 2103 | ServiceRef | String(name) |

Rules:

- Effects fold when they are applied (after `Receive`, record order), not when recorded. An
  effect after `Stop` is not folded (it is a protocol failure).
- Pending numbers and ask numbers come from one counter per incarnation, starting at 1. Outside
  asks (`sim.Ask`) number from a System-wide counter; their asker name is empty and boot is zero.
- Adapters and wrap functions are never folded; the message they make is folded when it is
  received.
- A `TimerKey` field in a product message folds as `String` (no tag). `Duration`, `Mono`, `Wall`
  fold as `Int64`; `ID` as `Bytes`; `Incarnation` as `String(name)`, `Bytes(boot)`.
- `foldState` adds, per up actor after `busy`: `Uint64(timers)`, `Uint64(pending answers)`,
  `Uint64(watches)`.
- Live computes no trace hash. `Fold` is used there only for optional tracing.

Goldens: P4 sets the new pins for kv; P6 and P7 for the products (D14, plan section 9).

## 6. dstgen specification

`dst/cmd/dstgen`, built on `go/ast` + `go/types` (D11). Run by `go generate` from one
`//go:generate go run github.com/manifesterio/mds/dst/cmd/dstgen` line per package.

### 6.1 Annotations

Written as a line comment directly above the declaration (or above a `type (...)` group, which
then applies to every type in the group).

| Annotation | On | Meaning |
|---|---|---|
| `//dst:sum` | an interface type | A sealed sum. It must embed `actor.Payload` and declare exactly one unexported marker method `is<Name>()`. Also gets `//sumtype:decl` semantics (dstgen writes the comment if missing). |
| `//dst:cases <sum>` | struct or named types | Each type is a case of `<sum>` (same package): dstgen writes the marker method, `Tag() uint64` and `Fold`. |
| `//dst:payload` | struct or named types | Not in a sum: dstgen writes `Tag` and `Fold`. |
| `//dst:answer <Type>` | one case of an IO sum | The case is a `Request` answered by `<Type>` (a Payload): dstgen writes `AsRequest() (<sum>, <Type>)`. |
| `//dst:state` | the actor's state struct | dstgen writes `StateHash() uint64` that folds every field in order. Fields tagged `dst:"skip"` are left out (caches, metrics). |
| `//dst:fold manual` | with `cases` or `payload` | dstgen writes marker and `Tag` only; the hand-written `Fold` stays. It must start with `h.Uint64(<tag>)` or `h.Uint64(x.Tag())`, checked. |

### 6.2 Generated code

One file per package, `zz_dst_gen.go`, header `// Code generated by dstgen. DO NOT EDIT.`,
gofmt'ed, ASCII only. For each case: `func (T) is<Sum>() {}`, `func (T) Tag() uint64 { return N }`,
`func (x T) Fold(h *trace.Hash)` that writes `h.Uint64(N)` then each field in declaration order:

| Field type | Fold |
|---|---|
| bool | `h.Bool` |
| signed integers, named or not | `h.Int64(int64(v))` |
| unsigned integers | `h.Uint64(uint64(v))` |
| float32/64 | `h.Uint64(math.Float64bits(float64(v)))` |
| string, named or not | `h.String` |
| `[]byte` | `h.Bytes` |
| `[N]byte` (ID) | `h.Bytes(v[:])` |
| a type with `Fold(*trace.Hash)` (Payload, refs, interfaces that embed Payload) | `v.Fold(h)`; a nil interface folds as `h.Uint64(0)` |
| other struct | its fields inline, in order |
| slice, array | `h.Uint64(len)`, then each element |
| map with ordered keys | `h.Uint64(len)`, then key and value in sorted key order |
| pointer, func, chan, interface without Fold, unsafe, map with unordered keys | generate-time error |

### 6.3 `dst.tags`

One file per package, next to the code, checked in. It is the only source of tag numbers.

```
# dst.tags: append-only. Never change a number. Never reuse a number.
# <tag> <sum or "-"> <TypeName>
1   runtime.EventData   NodeStarted
2   runtime.EventData   StopRequest
101 runtime.Action      SetTimer
4   -                   serverReply
3   runtime.EventData   -            # retired: the type was deleted
```

- A new case gets `max(tags of its sum) + 1`; a new payload gets `max(payload tags) + 1`. If
  that number is already in the file, dstgen stops and asks for a manual line.
- A deleted type keeps its line with the name `-` (retired). A renamed type may have its name
  edited by hand; its number stays.
- `dstgen -check -base <rev>` fails if, against `<rev>`, any line's number changed, any number
  was removed or reused, or two lines share a number.

### 6.4 Importing today's tags (P3)

`dstgen -import` reads each package's existing `func (T) Tag() uint64 { return N }` methods, and
for types with a hand-written `Fold` but no `Tag`, the literal of a first statement
`h.Uint64(N)`, and writes `dst.tags`. P3 then removes the hand-written marker, `Tag` and `Fold`
of each type whose generated `Fold` writes the same bytes. Proof: every golden is unchanged.
A type whose bytes differ (for example `contract` folds that write 200/300 for a nil value, or
the broker `ObjectCall` wrapper that keeps the four old tags) gets `//dst:fold manual` in P3;
whether to normalise it later is a P6/P7 choice inside their golden commits.

### 6.5 Errors

dstgen exits non-zero, naming file:line, for: an annotation on the wrong kind of declaration;
an unknown sum in `//dst:cases`; a sum without `actor.Payload` or with the wrong marker name;
a case listed in two sums; an `//dst:answer` type that is not a Payload or on a type that is not
a case of a sum; an unfoldable field type (6.2); a missing or duplicate tag; a manual `Fold`
that does not start with its tag; a generated file edited by hand (the check in 6.6).

### 6.6 Freshness check

`make -C dst gen-check`, and the same target in every product module, runs `go generate ./...`
into a temp copy and `dstgen -check -base origin/mainline`; a difference fails. It is part of
GATES-FAST from P3 on.

### 6.7 Amendments made while building dstgen (P3)

These refine 6.1..6.6; where they differ, this section wins.

1. `dst.tags` lines are `<tag> <TypeName>` (no sum column: the sum is in the code). A retired
   line is `<tag> -`. dstgen retires a line itself when the type no longer exists in the
   package; a type that exists but is not annotated keeps its line (the `-import` workflow).
2. A case may belong to several sums: `//dst:cases A B` writes one marker per sum and one `Tag`.
   The old API needs it (kv's `storePut` is a store request and a server output; the kernel
   harness's `put`). `//dst:answer` still needs exactly one sum.
3. Tag allocation: a new type gets one more than the highest tag of its range (types sharing a
   sum; or all payloads). If that number is held by another range, it gets one more than the
   highest tag in the file. dstgen never stops to ask; both rules are append-only.
4. dstgen does not edit source: a `//dst:sum` without `//sumtype:decl` is an error. `//dst:sum open`
   declares a sum whose switches need not be exhaustive (test harnesses that handle only some
   inputs); it must not have `//sumtype:decl`. The sum's
   method set must include `Fold(*trace.Hash)` (through `actor.Payload`, or `machine.Message`
   until P4 deletes it).
5. Generated files: `zz_dst_gen.go` (package files), `zz_dst_gen_test.go` (types in the
   package's `_test.go` files), `zz_dst_gen_x_test.go` (the external `pkg_test` package).
   Before generating, dstgen replaces existing generated files with a bare package clause, so
   stale output never feeds back.
6. Flags: `-import`, `-check`, `-base <rev>`. `make -C dst build` runs `gen-check`
   (`dstgen -check -base $(DSTGEN_BASE) ./...`, default `mainline`). A missing `dst.tags` at the
   base revision compares as empty. Products add the same target when they adopt dstgen (P6, P7).
7. `//dst:state` writes `func (x *T) StateHash() uint64`; fields tagged `dst:"skip"` are left out
   (an unfoldable field such as a pointer must be skipped explicitly). Fixed-size byte arrays fold
   as `Bytes(v[:])`; other arrays as `Uint64(len)` then each element.

## 7. Open items: closed

### O1 Perform typing: generic `Request[IO, Rep]` constraint, method written by dstgen

Options considered:

1. dstgen-generated per-request helpers from `//dst:answer` (`runtime.PerformLogAppend(o, req,
   adapt)`). Typed, but every IO case gets its own function name: the call site no longer says
   `Perform`, and the helper set grows with every case.
2. Runtime type check: `Perform(o, req IO, adapt any)`, a protocol failure on mismatch. One name,
   but a wrong answer type is found only when a seed runs that path.
3. A generic marker interface. Go cannot write "Req is a case of IO" as a constraint, because a
   constraint cannot embed the type parameter IO. But a method can name both:
   `type Request[IO, Rep Payload] interface { Payload; AsRequest() (IO, Rep) }`, and
   `Perform[In, IO, Rep Payload, Req Request[IO, Rep]](o *Outbox[In, IO], req Req, adapt func(Rep) In)`.
   Inference: `In` and `IO` come from `o`, `Req` from `req`, `Rep` from `adapt`. A case of another
   sum, or an adapt with the wrong answer type, fails to compile.

Choice: 3, with the method written by dstgen from `//dst:answer` (so it combines 1's annotation
with one generic name). The same constraint types `sim.Answer`, `sim.Forward` and `live.Answer`,
so the executor's answer is checked at compile time too. `AsRequest` returns the value as an
`IO` so the runtime can hand it to the executor without reflection.

### O2 Sub semantics: everything except Stop, scoped by a name

Options considered: (a) a sub may record only self-directed effects (timers); (b) a sub may
record everything, including `Stop`, sharing the parent's scope; (c) everything except `Stop`,
in its own named scope.

Choice: c. The broker sim session needs timers, `Perform` (connect) and `Do` (send); the flow
helper will need `Ask`/`Call`. Sharing the parent's scope (b) breaks two components with the
same timer key, and makes a component's reset forget the parent's work. So `Sub(o, name, wrap)`
takes a name (an identity label, not wiring): keys and `ForgetPending` are scoped to it (sections
3.3 and G8). `Stop` stays the parent's decision: a component reports trouble in its own message
and the parent decides. The sketch's `Sub(o, wrap)` gained the `name` argument.

### O3 Fold format: section 5

Effects fold at apply time with tags 2001..2018; refs 2101..2103; `foldState` gains three counts.
The range is above every product tag in use (max today: 11xx in rebalance and broker).

### O4 Watch for outside callers in live: confirmed 1:1 with CallAbandoned, with one rule

Today the gRPC layer (`server.call`) sends `CallAbandoned{Call}` when the context ends and the
call was not yet answered (`forget` under the mutex). Rebalance then drops the call from the
park list, the group queue or the pending write (`abandon`, `abandonParked`). With the new API,
`live.Ask` ends the outside asker when its context ends, and the runtime delivers each `gone`
registered by `Watch` (G6). The race is decided the same way as today: under the Host's lock,
either the reply reached the waiting handler first (no `gone`), or the context ended first
(`gone`, and the late reply is dropped).

The rule that makes it 1:1: rebalance must `Watch` every call it keeps past the `Receive` that
received it (parked join/sync, a call queued behind a busy group, a call waiting on a write,
a describe or commit waiting on the replica). A call answered in the same `Receive` needs no
watch. Today CallAbandoned is also sent for those, and rebalance ignores it; the new behaviour
skips that no-op.

The sim side is the same: the controlplane sim's group host gives each call a deadline and sends
CallAbandoned when it passes first; that becomes `sim.Ask(..., within, done)`.

Errors and timeouts of the gRPC handlers do not change: `products.go` section 2 shows `call()` and
`ask()` mapping `live.Ask`'s three outcomes to exactly today's codes.

### O5 Executors may Tell: confirmed

A sim executor holds the `*sim.System` (`ExecCtx.System()`), and `sim.Tell(system, ref, d, msg)`
delivers like any host send, on the executor's lane (section 3.4). The broker's sim executor turns
`Do(core.Send)` into a `Tell` of `core.BytesReceived` to the client actor that owns the
connection, after the per-pair delay; a connection reset fault is a `Tell` of `core.ConnClosed`.
Live: the socket reader goroutine calls `live.Tell`. No service sends unsolicited messages (D22).

## 9. Changes made while validating against the products

Each snippet in `products.go` and the kv sketch was checked by hand against the API in
Appendix A. Changes:

1. `Out` renamed `Outbox`, parameter `out` renamed `outbox` (D3).
2. kv server: `actor.Tell(out, s.store, storePut{...})` did not type-check (`s.store` is a
   `ServiceRef`); now `actor.TellService`.
3. kv store: `Handle(..., reply sim.ReplyTo[...])` became `sim.Responder[storeReply]` (the
   name `ReplyTo` belongs to actor asks); `actor.HashMap` became `trace.StringMap` (a small helper
   added to `dst/core/trace`).
4. Sum interfaces must embed `actor.Payload`, or `Actor[serverReq, ...]` does not satisfy its
   constraint. Fixed in `server.go`, `store.go`, `client.go`; dstgen enforces it.
5. `Props.Boot` is `func(self Incarnation) In` (the replica and broker boot messages carry
   `self`); `Env.Self()` added because both factories keep `self` today.
6. `sim.AddService` needs explicit type arguments (`[storeReq, storeReply]`): Go does not infer
   them from a concrete type that implements the interface.
7. `sim.Ask` is callback-based (`within, done`), not blocking: host code cannot block inside a
   discrete-event run.
8. `Perform` gained the fourth type parameter `Req Request[IO, Rep]` (O1).
9. `Sub` gained a `name` argument (O2).
10. Rebalance has no product IO: its log writes go through the replica. The sketch's
    `actor.Perform(o, runtime.LogSubmit{...})` became `actor.Ask(o, m.replica,
    ControlPlaneDeliver{ReplyTo, Op}, ...)`, and its IO type is `actor.NoIO`.
11. Rebalance answers `rebalance.Reply{Err, Body}`, not `JoinAnswer`, so the gRPC handlers keep
    mapping error codes as today.
12. The sketch said the replica Tells rebalance `RoleChanged`. That would change the replica's
    protocol and miss the "replica loop ended" case. Kept today's design instead: the server's
    `AfterReceive` hook sends it with `live.Tell`.
13. `live.OnLoop` added for `GetStatus` and `BrokerHeartbeat`, which today run code on the
    replica loop through the inject channel.
14. `live.Tell` added (outside sends: role hook, socket readers); `live.ErrHostStopped` added so
    handlers can map "host stopped" to today's `ErrUnavailable`.
15. `sim.Answer` on a `Do`'d request drops the answer quietly (the replica fire-and-forgets
    `ObjectDelete`).
16. Broker `Send` loses `Req` and moves to `Do`; `SendDone` is deleted (nothing reads it).
17. Effect and ref tags use 2001..2199, because rebalance and broker already use 1001..1199.
18. `sim.System` keeps `Start/RunUntil/Finish` and the lifecycle calls of `kernel.World`, used
    by both products' simulators.

## 10. Points to confirm at the gate

These are choices the plan did not spell out. All five were approved at the P1 gate.

1. **Per-pair FIFO** (section 3.4, G2): sends from one source to one actor at one time keep
   order. Products drop their own lanes.
2. **Live never restarts in process** (section 3.7): one actor's end stops the Host.
3. **`SiteStaleTimer` retired** in rebalance (8.2): keyed timers make it meaningless.
4. **RoleChanged stays outside the replica** (change 12).
5. **Watch rule for rebalance** (O4): watch only calls kept past their `Receive`.

## Appendix A. Frozen API (verbatim copy of `api.go`)

```go
//go:build ignore

// DESIGN SKETCH, NOT COMPILED. The frozen dst API (P1, ADR.md). Three packages
// are shown in one file: actor (dst/core/actor), sim (dst/sim) and live
// (dst/runtime/live). Bodies are omitted; doc comments are the contract.
// Section numbers (G1..G10, O1..O5) refer to ADR.md.
package actor

// ===================== package actor (dst/core/actor) =====================
// What product code imports. Deterministic, no goroutines, safe in production.

// ---- time and identity ----

// Mono is node-local monotonic time in nanoseconds. In a simulation it
// includes the fixed clock skew of the node. Was machine.NodeTime.
type Mono int64

// Wall is UTC in nanoseconds since the Unix epoch. Was machine.RealTime.
type Wall int64

// Duration is a length of time in nanoseconds.
type Duration int64

// Units of Duration.
const (
	Nanosecond  Duration = 1
	Microsecond          = 1000 * Nanosecond
	Millisecond          = 1000 * Microsecond
	Second               = 1000 * Millisecond
)

// Now is the time an actor sees for one Receive.
type Now struct {
	Mono Mono // use for deadlines and leases
	Wall Wall // UTC
}

// ID is a 16-byte id drawn from the seeded random stream (Rand.NewID).
type ID [16]byte

// Incarnation names one boot of one actor: its Props.Name and a boot number
// that is new for every boot. Was machine.NodeInstance. It is an identity
// label for logs, facts and storage keys; it is never used to send.
type Incarnation struct {
	Name string
	Boot ID
}

// ---- messages ----

// Payload is every message, request, answer and IO value. Fold writes the
// value into the trace hash: its frozen tag first, then its fields. dstgen
// writes Fold (ADR section 6); hand-written Fold stays legal with
// //dst:fold manual.
type Payload interface{ Fold(h *trace.Hash) }

// NoIO is the IO type of an actor that does no product IO. It has no cases,
// so Do and Perform cannot be called on an Outbox[In, NoIO].
type NoIO interface {
	Payload
	noIO()
}

// Request ties one case of an IO sum to its answer type, so Perform and the
// executors' Answer are checked at compile time (O1). dstgen writes the
// method from a //dst:answer annotation; product code never calls it.
// AsRequest returns the value itself as an IO and the zero answer.
type Request[IO, Rep Payload] interface {
	Payload
	AsRequest() (IO, Rep)
}

// ---- the actor ----

// Actor is one state machine with one input protocol In and one product IO
// sum IO. Receive is the only place its state changes; it never blocks and
// never does IO. Everything it wants done is recorded on outbox and carried
// out by the runtime after Receive returns (G1).
//
// StateHash is a hash of the whole state. The sim runtime folds it into the
// trace hash after every Receive.
type Actor[In, IO Payload] interface {
	Receive(now Now, msg In, outbox *Outbox[In, IO])
	StateHash() uint64
}

// Props says how to run one actor. It is the same value in sim and live.
type Props[In, IO Payload] struct {
	// Name is the identity label of the actor (logs, trace, facts). Unique in
	// one System or Host. Not used for wiring.
	Name string
	// New builds the actor. It is called on every boot; nothing survives a
	// crash, so it never returns an old actor. Required.
	New func(env Env) Actor[In, IO]
	// Boot, when set, is the first message of every boot. It is received
	// before anything else of that incarnation.
	Boot func(self Incarnation) In
	// StopMsg, when set, makes the graceful-stop request. It is delivered
	// with Control priority. Nil: a graceful stop is not allowed (sim:
	// protocol failure; live: the actor is killed at once).
	StopMsg func(deadline Mono) In
	// Priority picks the inbox of a message. Control is always received
	// before Data. Nil: everything is Data.
	Priority func(msg In) Priority
	// Restart decides when the next incarnation boots after one ended. Nil,
	// or ok=false: the actor stays down until a host boots it (sim). Live
	// does not restart in process (ADR section 3.7).
	Restart RestartPolicy
}

// Priority picks one of the two inboxes of an actor. Was machine.Class.
type Priority uint8

// The two priorities.
const (
	Control Priority = iota
	Data
)

// End says how an incarnation ended.
type End uint8

// The ways an incarnation can end.
const (
	Crash End = iota // killed from outside (nemesis, attrition, stop deadline, panic)
	Trip             // the actor asked for a restart: its memory is not trusted
	Exit             // the actor finished a graceful stop
)

// RestartPolicy returns how long after an End the next boot starts, or
// ok=false for no restart. It draws only from r.
type RestartPolicy func(how End, r Rand) (after Duration, ok bool)

// Env is the only way randomness, buggify and assertions reach an actor.
// Time is not here: it comes with each Receive.
type Env interface {
	Rand
	Faults
	Assertions
	// Self is the incarnation this Env was made for.
	Self() Incarnation
}

// Rand is the seeded random stream of the run, as an actor sees it.
type Rand interface {
	Uint64() uint64
	Intn(n int) int             // [0, n); 0 and no draw when n <= 0
	Between(lo, hi int64) int64 // [lo, hi]; lo and no draw when hi <= lo
	Chance(p float64) bool      // no draw when p <= 0
	Duration(lo, hi Duration) Duration
	NewID() ID
}

// Faults is buggify (unchanged from machine.Faults).
type Faults interface {
	Maybe(site fault.Site) bool
	MaybeP(site fault.Site, p float64) bool
	Fault(site fault.Site, p float64) bool
}

// Assertions record properties (unchanged from machine.Assertions).
type Assertions interface {
	Always(cond bool, p assert.Always, details ...assert.Pair)
	AlwaysOrUnreachable(cond bool, p assert.AlwaysOrUnreachable, details ...assert.Pair)
	Sometimes(cond bool, p assert.Sometimes)
	Reachable(p assert.Reachable)
	Unreachable(p assert.Unreachable, details ...assert.Pair)
}

// Fact, Field and the FieldValue cases (Int64Value, Uint64Value, StringValue,
// Bool, Bytes) move unchanged from package machine, with their frozen tags
// 401..405 and 501.
type Fact struct {
	Name   string
	Fields []Field
}

// ---- handles: plain typed values, foldable, safe in messages and state ----

// EntityID is the opaque identity behind an EntityRef: which runtime made
// it, which slot, and the actor's Name. Products never build one.
type EntityID struct{ /* runtime id, slot, name */ }

// Entity is any EntityRef, for lifecycle calls that do not need the message
// type (sim.System.Crash, Pause, ...).
type Entity interface{ EntityID() EntityID }

// EntityRef[P] is the stable handle of an actor whose protocol is P. It
// survives restarts: a message sent to it goes to whatever incarnation is up
// when it arrives, and is dropped if none is. Only Spawn makes one. The zero
// EntityRef, or one of another runtime, is a protocol failure when used.
type EntityRef[P Payload] struct{ id EntityID }

func (r EntityRef[P]) EntityID() EntityID
func (r EntityRef[P]) Name() string
func (r EntityRef[P]) IsZero() bool
func (r EntityRef[P]) Fold(h *trace.Hash) // ADR section 5: tag 1101, name

// ReplyTo[R] is the handle an Ask puts into its request. It names one ask of
// one asker incarnation (an actor, or an outside caller of sim.Ask or
// live.Ask). It dies with that incarnation: Reply to a dead ReplyTo is
// dropped (G4). Only the runtime makes one. Comparable, so products may use
// it as a map key.
type ReplyTo[R Payload] struct{ /* asker kind, slot, boot, ask number */ }

func (r ReplyTo[R]) IsZero() bool
func (r ReplyTo[R]) Fold(h *trace.Hash) // tag 1102, asker name, boot, ask number

// ServiceRef[Req, Rep] is the handle of a simulated outside service (sim
// only, but the type lives here so actors can hold it).
type ServiceRef[Req, Rep Payload] struct{ /* runtime id, slot, name */ }

func (r ServiceRef[Req, Rep]) Name() string
func (r ServiceRef[Req, Rep]) Fold(h *trace.Hash) // tag 1103, name

// TimerKey names a timer of one actor. Products build keys from their own
// data, e.g. TimerKey("session/" + group + "/" + member), so an actor needs
// no timer-id counter and no owners map.
type TimerKey string

// ---- Outbox: the effects of one Receive ----

// Outbox records the effects of one Receive, in order. The runtime carries
// them out after Receive returns, in that order (G1). An Outbox is lent for
// one Receive only: using it later is a protocol failure.
type Outbox[In, IO Payload] struct{ /* recorded effects */ }

// Self is my own stable handle, to give to others.
func (o *Outbox[In, IO]) Self() EntityRef[In]

// TellSelf puts msg in my inbox now, behind messages already there. Same as
// After(0, msg). It dies with this incarnation.
func (o *Outbox[In, IO]) TellSelf(msg In)

// After delivers msg to this incarnation after d of node time. One-shot,
// nothing to cancel; dropped by Stop and ForgetPending. d < 0 counts as 0.
func (o *Outbox[In, IO]) After(d Duration, msg In)

// StartTimer delivers msg after d, under key. A timer with the same key is
// replaced, including one that fired but is not yet received (G3).
func (o *Outbox[In, IO]) StartTimer(key TimerKey, d Duration, msg In)

// CancelTimer drops the timer key, including one that fired but is not yet
// received (G3). An unknown key is a no-op.
func (o *Outbox[In, IO]) CancelTimer(key TimerKey)

// Do hands io to the executor. Its results, if any, come back as my own
// messages that the executor sends (broker sockets: BytesReceived). Use
// Perform when the IO has one typed answer.
func (o *Outbox[In, IO]) Do(io IO)

// Stop ends this incarnation: how is Trip or Exit. Everything it owned is
// dropped (G7). It must be the last effect of the Receive.
func (o *Outbox[In, IO]) Stop(how End, cause string)

// Fact appends f to the timeline (sim) or the trace log (live). It never
// changes behaviour.
func (o *Outbox[In, IO]) Fact(f Fact)

// ForgetPending drops every timer and every Ask, Call and Perform answer
// this actor is still waiting for, without ending the incarnation (G5).
// Answers that arrive later are dropped. Watches stay. Through a Sub, it
```
