DST-1  Two event schedulers in dst: merge sched into the sim queue
======================================================================
Type:       Tech debt
Priority:   Medium
Component:  dst/core/sched, dst/sim (queue.go), dst/core/clock, dst/core/syncclock,
            shared/clock
Reporter:   (dst redesign, P2)
Created:    2026-11-24
Status:     Open (deferred: plan D17 "clock-package merge")
Blocks:     nothing in P2..P8
Related:    docs/design/dst-redesign-plan.md D17; docs/design/dst-next/ADR.md section 4 (G2)

Summary
-------
dst has two separate event schedulers with the same ordering rule (time, seeded tie,
insertion seq):

  1. dst/core/sched (was dst/sched): a general loop that runs closures at virtual times.
     Users: dst/core/clock, dst/core/syncclock, dst/core/realclock (only its TimeNs type),
     and shared/clock (fake clock; production module).
  2. dst/sim/queue.go (copied from the old kernel): the simulator's own heap with lanes, entry kinds folded into
     the trace hash, cancel by EntryID, and dropIncarnation.

Background
----------
sched is the older, general scheduler. When the kernel needed lanes, hashed entry kinds,
cancel-by-id and dropping a dead incarnation's entries, it grew its own queue instead of
extending sched. sched stayed behind to drive fake time for the clocks. Not confirmed from
git history; inferred from the code.

Found in P2: the plan put sched under dst/sim, but its only users are the clocks and
shared/clock (production code), so core -> sim and product -> sim imports appeared. P2 moved
it to dst/core/sched instead. That fixes the layering; the duplication remains.

Problem
-------
- Two implementations of one ordering rule (heap, tie draw, seq). A fix to one (for example
  a tie-draw change) can silently diverge from the other.
- Two notions of time: sched.TimeNs vs machine.NodeTime/Duration (actor.Mono/Duration after P4).
- A reader of dst meets two schedulers and has to learn why.

Proposal
--------
After P8 (the new sim.System queue is the only simulator queue):
  1. Extract one deterministic queue into dst/core/sched with the features both need
     (lanes, cancel by id, kinds as opaque labels; trace folding stays in sim).
  2. Rebuild sim.System's queue and dst/core/clock/syncclock on it.
  3. Replace sched.TimeNs with actor.Mono/actor.Duration.
  4. Delete the duplicate heap.

Acceptance criteria
-------------------
- One heap implementation in dst (grep finds one (at, tie, seq) comparator).
- GATES-FULL green; golden hashes unchanged, or regenerated in one golden commit with the
  reason (plan section 9).
- dst/core does not import dst/sim (depguard).
- shared/clock behaviour unchanged (its tests pass without edits to expected values).

Notes
-----
- Do not do this during P3..P7: it would move hashes in the middle of migrations.


DST-2  Flaky broker integration test: TestCompressionRoundTrip gets cp ErrUnavailable
======================================================================
Type:       Bug (test flake)
Priority:   Low
Component:  broker/test/integrationtest (compression_test.go:52, cpproc_test.go)
Reporter:   (dst redesign, P3 commit hook)
Created:    2026-11-24
Status:     Fixed (P5 commit)

Summary
-------
The pre-commit hook (make build -> broker it) failed once with
  compression_test.go:52: cp: ErrUnavailable
right after mdscontrolplane logged "listening". The same test passed when re-run alone
(go test -tags integration -run TestCompressionRoundTrip ./test/integrationtest/, 38 s).
The commit under test (P3: dstgen) changed no broker or controlplane code.

Cause (verified)
----------------
cpproc_test.go waitReady treated any role but "down" as ready, so the test started while
the control plane was still standby; a standby answers CreateTopic with ErrUnavailable.
waitReady now waits for role "active". Passed 3/3 runs after the fix.

First guess (superseded)
------------------------
The test's first control-plane call races the control plane's readiness: "listening" is
logged before the replica is active (claimed its epoch), and a call in that window is
answered ErrUnavailable. The test does not retry or wait for GetStatus to report ready.

Proposal
--------
Make the test helper wait until GetStatus succeeds (the server returns Unavailable while
not ready), or retry the first call with a short backoff, before the test body starts.

Acceptance criteria
-------------------
- go test -tags integration -count=20 -run TestCompressionRoundTrip ./test/integrationtest/
  passes 20/20.


DST-3  ControlPlaneDone.Req carries a log slot under a request-id name
======================================================================
Type:       Tech debt
Priority:   Low
Component:  controlplane/internal/runtime (event.go), controlplane/internal/controlplane/metadb
Created:    2026-11-24
Status:     Done

Summary
-------
After the actor migration nothing routes answers by request id (callers hold a ReplyTo), but
runtime.ControlPlaneDone keeps a field Req. metadb fills it with the log slot an operation was
applied at (metadb/entry.go), and the idempotent-replay window stores and returns it. The name
says "request" while the value is a slot.

Proposal
--------
Rename the field to Slot (runtime.LogPosition) in runtime, metadb and their tests. It is folded
into the trace hash, so the rename moves no hash, but a type change would: do it in a phase that
regenerates controlplane goldens anyway.

Acceptance criteria
-------------------
- No field named Req in controlplane/internal/runtime.
- Controlplane goldens unchanged, or regenerated with the reason.

Resolution
----------
Renamed ControlPlaneDone.Req → Slot (LogPosition); metadb Apply writes Slot. Fold now uses
Int64 (same bits as the old Uint64), so controlplane goldens stay unchanged.


DST-4  Simulator coverage notes match timer messages by their trace fold
======================================================================
Type:       Tech debt
Priority:   Low
Component:  controlplane/internal/verify/simulator (groups.go)
Created:    2026-11-24
Status:     Open

Summary
-------
The rebalance actor's timer messages (writeTimedOut, loadRetryDue, ...) are private to package
rebalance. The simulator's group host notes the coverage paths writeTimerEndsTerm,
refusedLoadReadSentAgain and failedWriteEndsTerm by recording the trace fold of each StartTimer
or After message it sees in the actor's effects, and matching later received messages by fold.
It works, but it couples the host to fold bytes instead of to meaning.

Proposal
--------
Either export a small predicate from rebalance (e.g. rebalance.IsWriteTimeout(in Input) bool)
for host checks, or record the coverage facts inside rebalance with env.Reachable at the place
the behaviour happens, and drop the host-side matching.

Acceptance criteria
-------------------
- No fold-matching in the simulator's group host.
- The controlplane campaign still reaches all expected coverage paths.


DST-6  controlplane/contract still folds its operations and responses by hand
======================================================================
Type:       Tech debt
Priority:   Low
Component:  controlplane/contract (fold.go, 27 Fold methods)
Created:    2026-11-25
Status:     Open

Summary
-------
Every product message is now generated by dstgen except the contract operation and response
types (and two deliberate //dst:fold manual cases: broker ObjectCall/ObjectDone, rebalance.Reply).
contract folds a nil Operation as tag 200 and a nil Response as 300, which dstgen does not do
(it folds a nil interface as 0).

Proposal
--------
Annotate contract with //dst:cases / //dst:payload after importing its tags, and accept the
nil-fold change in a golden-regenerating commit; or keep fold.go and mark the types
//dst:fold manual so dstgen still owns the tags.

Acceptance criteria
-------------------
- No hand-written Fold in controlplane/contract, or every one is //dst:fold manual.
- Goldens unchanged, or regenerated with the reason.


DST-8  Package actor exports its runtime seam to product code
======================================================================
Type:       API hygiene
Priority:   Low
Component:  dst/core/actor (erase.go)
Created:    2026-11-25
Status:     Open

Summary
-------
sim and live need Effect, EffectKind, Binding, NewOutbox, Close, NewEntityRef, NewReplyTo,
NewServiceRef, As, NewOwner, Asker, ReplyID, EntityID, ServiceID. They are exported from package
actor, so product code can build refs or outboxes by hand and bypass the runtime.

Proposal
--------
Either move the seam to dst/internal/actorrt (importable by dst/sim and dst/runtime/live only;
actor keeps thin unexported accessors), or add a forbidigo rule in the product golangci configs
that forbids these identifiers outside tests.

Acceptance criteria
-------------------
- Product non-test code cannot use the runtime seam (compile error or lint error).
- sim and live unchanged in behaviour; GATES-FULL green.
